# Review and validation, 5 September 2026

Reviewed every runtime source file, the manifest, installation documentation,
and the marketplace's catalog/preview contract. Changes target version 0.4.0.

## Findings addressed

| Severity | Finding | Resolution |
| --- | --- | --- |
| P1 | A persisted address could identify a different Nautilus process after a compositor restart. | Ownership now requires an address, process ID, matching compositor instance, Nautilus class, and a live window tag. The tag also prevents same-process address reuse from transferring ownership. Old address-only records are ignored. |
| P1 | The background launcher inherited the helper's flock descriptor. A long-lived launcher could block later controls. | Close descriptor 9 in the launched child. A regression test checks the inherited descriptor directly. |
| P2 | Shell reload queried status without restoring `opened` or restarting focus handling. | Successful controller completion reconciles both state and the focus warmup. |
| P2 | Failed hide operations left an optimistic closed bar state, and show errors were overwritten by cleanup output. | Query actual state after failures, retain stderr in status/tooltip, and preserve newer queued commands. |
| P2 | A click during startup could be lost before preference/screen discovery finished. | Queue the operation until initialization is ready. |
| P2 | An in-flight focus result could arrive after a new open/hide cycle. | Discard results from older operation generations. |
| P2 | Focusing a separate Nautilus dialog was treated as leaving the file manager. | Keep the shelf open while the same Nautilus process has focus. This also includes its other windows, as documented. |
| P2 | A launch with multiple candidates could later select the last remaining unrelated window. | Stop on ambiguous candidates without moving any of them. |
| P2 | Compositor query failure could be reported as a normally closed window. | Propagate query failures as errors. |
| P2 | The README described a locally installed shortcut as a plugin default and omitted removal recovery. | Make the binding explicitly optional; document requirements, disable/remove, and hidden-window recovery. |
| P2 | The marketplace page had no preview and only a minimal summary. Expanding the README would not affect it. | Add the supported 433-character manifest summary and root preview, plus a full README with three real screenshots. Document the exact-snapshot publication gate. |
| P3 | The service continuously spawned focus-check processes while Nautilus was focused. | Use compositor focus-change events to schedule further checks. |
| P3 | Unused state-file watching, duplicate monitor repositioning, and non-wrapping menu text added avoidable work or layout risk. | Remove the redundant watchers/call and wrap menu guidance. |

## Completion evidence

- Implementation and integration: real helper, QML service and bar widget updated.
- Automated validation: 12 helper tests and 7 service callback tests; Bash syntax,
  Omarchy manifest validation, image-format checks, and clean diff whitespace.
- CI: the regression and asset checks run on pushes and pull requests.
- Live validation: Omarchy 4.0.2 / Hyprland 0.56.2, 1920x1080 at scale 1.
  Left/right geometry was 844x1028 with reserved top-bar space; bottom was
  1888x680. Same-window reuse, parking, focus loss, reload recovery, rapid command

- Documentation/assets: installation, controls, layouts, optional bindings,
  troubleshooting, upgrade behavior, recovery, removal, and three inspected
  1920x1080 desktop screenshots using sample files.
- Operational readiness: prepared for repository review. Live marketplace
  publication requires a merged current-HEAD commit and marketplace approval.

## Validation limits and remaining design constraints

Standalone qmllint reports unresolved `qs.*` imports and Quickshell metadata
warnings outside the running shell. Live service/widget loading succeeded;
these warnings are not reported as a clean static lint pass.

Rotated/scaled and multiple-monitor selection have automated coverage. Physical
display reconnect, touch interaction, and end-to-end keyboard navigation of the
bar menu were not validated on this single-monitor host.

Nautilus does not expose a launch-specific window identifier here. Simultaneous
manual Nautilus launches remain a limitation of before/after window discovery;
an unrelated new window that appears alone before the requested window can be
indistinguishable. The README advises avoiding concurrent launches. The helper
never adopts an existing unrelated window at startup and fails on simultaneous
multiple candidates. A fully isolated Nautilus instance would change its normal
D-Bus, desktop, and network-location behavior and was not introduced.

The plugin retains Nautilus windows on disable/removal. Recovery and the
address-only-state upgrade behavior are documented instead of closing user work.
